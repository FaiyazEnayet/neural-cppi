# Changelog

## [Unreleased]
### Added
- Honest chronological evaluation registry (`src/dhl/eval/registry.py`): named episodes with exact date endpoints, independence groups, legal training periods, prehistory embargo, a previously-viewed-judge flag, and predeclared test geography/asset family/dates. Training periods and training blocks are validated fail-closed at price-bar and feature-lookback granularity against the standard chrono episodes (train pre-2020, reserved 2020, COVID stress, validation 2021-2022, test 2023+); every chronological test set reports overlapping window counts alongside non-overlapping counts. New tests: `tests/test_stage3_neural_cppi_1.py` (independent date-count oracle, full-span training-pool rejection, lookback embargo crossing, judge-window flags, predeclare recording, window-count separation, shared seed schedule, across-seed summary).
- Valid historical prehistory for rollout features (`src/dhl/experiments/cppi_learned.py`): `rollout` now accepts pre-window prices (`history`, shared 1-D or per-path 2-D) used for feature computation only. Features are computed on [history, S] and sliced to the window steps, so the first trade sees real pre-window state; wealth still starts at 100, holdings at zero, and charges at t0, so changing history can only move policy decisions, never pre-window profit or loss. The standard warm history is 60 actual trading observations (`WARM_LOOKBACK`); passing no history is the cold protocol, the documented reset semantics for a spliced block with no valid preceding context (features start at zero, never an invented drawdown). Warm and cold are named by `describe_protocol` and recorded in `evaluate` metrics (`protocol`, `history_days`, plus a `context_reserved` label for windows whose context extends into a reserved period). Malformed histories raise instead of misaligning features. New tests: `tests/test_causal_features.py` (future-price perturbation leaves earlier decisions bit-identical, nonzero first-trade features with real history plus an independent NumPy vol oracle, constant weights unaffected by history, history-sensitive weights with zero pre-window P&L, feature index alignment with the full path, horizon and ledger lengths unchanged, warm/cold protocol naming, history shape validation).
- Fail-closed experiment provenance (`src/dhl/eval/provenance.py` plus `scripts/reproduce_historical.py`): an experiment manifest records data paths with SHA-256 hashes, code commit and dirty status, dependencies, train seed, hyperparameters, selected windows, training exclusions, and timestamp. Loading validates the schema, data verification recomputes every hash, and any missing file, changed byte, or mismatched checkpoint hash raises instead of proceeding. Manifests reject absolute data paths and absolute user-specific paths anywhere in their text. Checkpoints load tensor-only, so arbitrary pickle payloads are refused. The reproduction script verifies a manifest from a fresh checkout and exits nonzero with an explicit error naming what is missing or changed. The private sealed runs adopt this guard; no private data or vendor API is needed to use it. New tests: `tests/test_stage3_neural_cppi_0_provenance.py` (manifest round-trip and rejection cases, hash verification, tampered and missing data, checkpoint mismatch abort, absolute-path rejection, reproduction script success and failure, tensor-only loading).
- Dependent-path uncertainty for chronological evaluation (`src/dhl/eval/chrono.py`): strictly nonoverlapping real windows (stride path_len + 1, so no price bar is shared; the inter-window return is dropped by design, matching the disjoint-window count in `src/dhl/eval/registry.py`), calendar block labels (month, quarter, year), a block-bootstrap percentile CI for paired differences that resamples market blocks as units, exact Clopper-Pearson upper bounds on terminal breach rates (closed form 1 - alpha ** (1/n) at zero observed breaches, no normal approximation), frozen-hyperparameter recording by SHA-256, an explicit post-selection label for previously viewed test episodes, and a sensitivity report across horizon, floor, and block length. The block bootstrap here is an evaluation device for intervals, not the training-time block bootstrap in `dhl.markets.real` that generates synthetic paths. New tests: `tests/test_stage3_neural_cppi_6.py` (no shared bars, calendar blocks, bootstrap determinism plus an independent resample oracle, blocks as the resampling unit, zero-breach closed form and the defining binomial property, frozen-config hashing, paired point estimates and CIs, seed/hash separation, post-selection labeling, sensitivity structure).
- Comparator ladder under one execution kernel (`src/dhl/benchmarks/cppi_rules.py`, `src/dhl/eval/comparators.py`): one strategy factory builds every rung (all cash; buy/hold with exact costs; plain m=4 CPPI; optimized fixed m CPPI; identical emergency brake CPPI; dynamic volatility CPPI; constant fraction of allowable CPPI budget; fixed cap exposure; simple trend-plus-vol CPPI; raw, CPPI-constrained, and constrained-plus-brake learned policies), and every rung runs through the same `rollout` with the same ledger, so floors, caps, financing rates, rebalance frequency, costs, and initial state match by construction. The brake rung applies the shipped emergency rule (vol above 0.35 halves the multiplier) to a classic proposal, so a braked learned policy is compared against a braked classic, not an unbraked one. A 1.0 cap wrapped around a trained 1.5 policy is recorded as the applied cap in its table row, not hidden. Budget fraction 1.0 reproduces classic CPPI exactly. Optimized multipliers are selected on tuning paths only and validated fail-closed against the episode registry or legal tuning splits. Every table row carries mean wealth, minimum wealth, breach counts, drawdown, turnover, fees, average leverage/exposure, a risk-adjusted metric, and mean floor shortfall, plus risk-return frontier points. No published numbers are regenerated by this change. New tests: `tests/test_comparator_parity.py` (factory conventions, budget parity, brake identity against the shipped wrapper, buy/hold and all-cash hand-computed oracles, table columns, tuning-only selection with registry rejection, clip disclosure, dynamic-vol and trend-vol behavior, fixed cap, frontier shortfall, learned rungs, fail-closed factory).
- Dependence-aware evaluation statistics (`src/dhl/eval/statistics.py`, plus a `paired_evaluate` enrichment in `src/dhl/eval/chrono.py`): event-family clustering so nested 252/504-day windows from one event count once (same explicit event label or overlapping intervals, transitive), per-window paired differences that fail closed on mismatched keys, family-equal aggregation reported alongside the window mean, horizon slices that never pool mixed horizons, interpretable per-window scales (terminal V_T, annualized log growth, worst intrawindow wealth, max drawdown, risk-budget utilization, trade notional, total fees, with missing inputs reported as absent, never zero), an episode-aware bootstrap interval that resamples families and labels itself exploratory with no independent-sample significance claim, a full seed x episode variation table, and a trial ledger that keeps negative variants in its multiplicity counts. Summaries render with a worst-case section (worst paired difference, worst drawdown, worst intrawindow wealth) that JSON parsing refuses to drop, and recomputing from the JSON reproduces the stored tables exactly. The private summary scripts (phase3/summarize.py, round4/summarize.py) are not in the public repo and are out of scope. No published numbers are regenerated by this change. New tests: `tests/test_statistics.py` (event clustering including nesting and transitivity, fail-closed pairing, family mean versus window mean, horizon slices, log-growth and window scales, family bootstrap oracle plus single-family collapse, seed x episode table, trial ledger negatives, JSON round-trip exactness and worst-case refusal, paired_evaluate enrichment with default behavior unchanged).
- Honest historical stress tiers (`src/dhl/markets/history_ext.py`, plus table metadata in `src/dhl/experiments/chrono_eval.py`): a six-tier catalog (2008 in-sample diagnostic for a pre-2020-trained model, genuinely unseen 2008 for a model trained strictly before 2008, held-out COVID Feb-Apr 2020, validation 2021-2022, reserved post-freeze 2023+ evaluation, and a monthly 1929-1933 proxy stress) with a fail-closed validator: the seen flag must match the actual training/eval window overlap, daily claims before 1940 are refused, SPY/TLT/GLD backcasting before each inception date is refused, and tuning cutoffs after a freeze date are refused. Every table `run_chrono_eval` writes now carries a validated metadata block stating frequency, training cutoff, proxy, dividends, and cash convention (cash 2% per year, negative cash at the same rate; SPY tables use adjusted close). The monthly proxy tier states its conventions only and loads no Depression series of any frequency. No published numbers are regenerated by this change. New tests: `tests/test_stage3_neural_cppi_4.py` (in-sample vs unseen classification, COVID holdout, post-freeze tuning refusal, monthly proxy completeness, daily Depression and ETF backcast rejection, missing metadata rejection, seen-flag consistency, chrono table metadata).
- Shared economics kernel enforcement (`src/dhl/backtest/execution.py`, `src/dhl/experiments/cppi_learned.py`, `src/dhl/experiments/cppi_multi.py`): portfolio weights are now validated fail-closed every step in the multi-asset rollout (nonnegative, summing to one within 1e-5), so the long-only no-borrowing claim is enforced rather than assumed; the single-asset rollout refuses to trade a path whose pre-trade wealth is nonpositive (the kernel requires positive wealth, and trading on produced negative holdings from long-only weights); the drawdown floor series is indexed consistently (F[j] is the floor set by the peak through date j - 1, and F[0] is the date-0 floor itself, which in drawdown mode is (1 - max_dd) * V0, not the fixed-floor parameter). New tests: `tests/test_stage3_neural_cppi_1_economics.py` (weight validation accept/reject, drawdown floor start and indexing, terminal-floor reasoning on a new-peak final move, fixed-floor series unchanged, bankrupt-path refusal with honest negative terminal wealth for a path solvent at its last trade, borrow accrual at an explicit borrow rate versus the cash rate, seeded self-financing and fee identities, a short-path multi-asset oracle, and the legacy diff table below).
### Fixed
- Validation labels in the chronological evaluation (`src/dhl/experiments/chrono_eval.py`, `src/dhl/eval/chrono.py`): the validation set is now exactly 2021-2022 (`VAL_START`), not 2020-2022; 2020 bars outside the COVID stress window are reserved and belong to no train/val/test bucket. `split_returns_by_date` gains an optional `val_start` for that gap, defaulting to the old behavior. The crash ablation (`src/dhl/experiments/crash_ablation.py`) now trains every variant under one shared seed schedule with matched budgets instead of seed, seed+1, ..., seed+7 across variants, and reports per-seed tables plus an across-seed summary; variants with different feature counts keep different parameter shapes by construction and are compared on replicated outcomes, not pretended-identical tensors. No published numbers are regenerated by this change.
- `rollout_multi` in `src/dhl/experiments/cppi_multi.py` now routes every rebalance through the shared trade-accounting kernel in `src/dhl/backtest/execution.py`: holdings move to the target weights of post-fee wealth and the fee is charged on the actual traded notional, so a fully invested path can no longer end a date with negative cash from fees alone. The old code charged the fee on the pre-fee target minus the grown old holding and then set the holding to the pre-fee target, so executed and charged notionals disagreed. The single-asset `rollout` now imports the same kernel's closed form with unchanged numbers (a golden fixture pins the previous terminal wealths exactly). The kernel solves the post-fee wealth equation exactly by scanning trade-sign breakpoints, stays differentiable for training, and keeps cash nonnegative for long-only weights. New tests: `tests/test_execution.py` (exact accounting identity on random fixtures, analytic buy/sell costs, all-cash charging no fees, an independent NumPy reference for a multi-asset rollout, float64/float32 agreement, jump properties, finite gradients, and the single-asset golden fixture).

### Docs

### Changed
- `rollout` in `src/dhl/experiments/cppi_learned.py` now keeps an explicit holdings ledger (cash, risky units, traded notional, fees) instead of a wealth shortcut: each rebalance solves the exact proportional-cost equation so the target weight holds on post-trade wealth and every fee is charged on the actual trade, and the terminal liquidation is charged on the true terminal holding value. The leverage cap and the funding assumption are now parameters (`cap=CAP`, `borrow_rate=None`, which borrows at the cash rate as before); existing callers and signatures are unchanged. Exact self-financing moves recorded experiment numbers slightly (the old approximation overcharged buys and the stale-value liquidation, undercharged sells); committed results were not regenerated. New fixture: `tests/test_stage3_neural_cppi_3_ledger.py` (self-financing identity at every trade, an independent scalar reference, and zero-return / buy-and-hold / cap=1 / cap>1 / fee-only property cases).

### Fixed
- The multi-horizon training loss now lives in `src/dhl/experiments/losses.py` as explicit named components (negative expected terminal wealth, terminal floor shortfall, anytime floor shortfall, turnover), each reported alongside the total. The anytime (pathwise) floor-shortfall term now ADDS to the minimization loss; a private-experiment variant of this objective previously subtracted it, so the two candidates trained with a positive anytime weight were corrupted tests of the anytime-shortfall hypothesis. Zero anytime weight reproduces the previous terminal-only objective exactly. New tests: `tests/test_losses.py` (shortfall raises the loss, finite-difference gradient matches autograd, zero-weight equivalence, finite gradients). The affected candidates are being re-evaluated privately with the corrected sign under identical training budgets; no results are published from this change.
- Three economics fail-opens found by measurement at HEAD, fixed in the kernel enforcement above. (1) `rollout_multi` silently accepted negative weights (implicit shorting) and risky sums above one (implicit borrowing at the cash rate, with no borrow-rate parameter), despite documenting a long-only sum-to-one contract. (2) In drawdown mode the returned floor series started with the fixed-floor parameter instead of the drawdown formula, so F[0] disagreed with every other date whenever floor differed from (1 - max_dd) * V0 (the defaults coincide, which hid it). (3) Single-asset `rollout` kept trading a bankrupt path: a levered weight into an 80% one-day crash drove wealth to -19.94 and the kernel then produced negative holdings from a long-only weight, so post-bankruptcy numbers flowed into breach statistics as if real. Legacy diff table (same real SPY returns, same block-bootstrap seeds, cost 20bp, floor 90, cap 1.5; old formula from the first parent of the NC3 merge 6962e353, funding identical on both sides since both borrow at r by default, so every difference is the exact fee solve): 30d classic m3 100.4112 -> 100.4112, m4 100.4355 -> 100.4355, m5 100.4465 -> 100.4466, buy-hold 100.9946 -> 100.9949, all-cash 100.2385 -> 100.2385 (identical, no trades); 63d m3 101.0017 -> 101.0017, m4 101.0891 -> 101.0892, m5 101.1441 -> 101.1442, buy-hold 102.5691 -> 102.5694, all-cash 100.5014 -> 100.5014. At 20bp the exact solve moves means by at most 3e-4; the material gap shows on the pinned analytic case (one step, fully invested, 100 -> 92.5 at 2% cost): old 88.69 -> new 88.8725, because the old code charged the entry fee on the pre-fee target (2.00 on 100) and liquidated on the stale pre-move holding (1.96 on 98), while the kernel charges the exact solve (entry 1.9608) and liquidates on the true terminal value (1.8137 on 90.6863). A stale test comment quoting the old 90.65/88.69 values is corrected to the current values. No published numbers are regenerated by this change; the multi-asset legacy comparison is not separately tabulated (the pre-P0-B multi code carried the same pre-fee-target approximation class, and the fixed-floor parity test already pins multi against single).

## [v1.2.2] - 2026-10-18
### Fixed
- Policy construction is now seeded *before* initialization everywhere it is trained: new `seeded_policy` helper (`torch.manual_seed(seed)` runs before the network is built) replaces bare `CPPIPolicy()` / `MultiAssetPolicy()` construction in the chronological, crash-ablation and multi-asset runners. Equal seeds now guarantee equal initializations regardless of construction order or preceding RNG state; the training functions still re-seed the torch stream at train start, and sampler/evaluation draws keep their separate `seed + epoch` / `seed + 999` numpy seeds. New `policy_init_hash` helper records a short SHA-256 fingerprint of the initial weights (logged by the runners). Regression tests: init hash depends only on the seed across polluted RNG states, and two fresh processes produce identical init and post-training hashes under deterministic CPU settings.

## [v1.2.1] - 2026-10-18
### Fixed
- `rollout` and `rollout_multi` now write the post-liquidation wealth into the final path point, so `path[:, -1] == V_T` for every path. Previously the liquidation cost was subtracted from `V_T` after the path was closed, so terminal and anytime breach statistics could disagree at the horizon. Regression tests: terminal-point equality on random paths, a hand-computed fixture where wealth sits just above the floor before liquidation but below it after (the anytime breach now registers), and a zero-cost fixture confirming the economic path is unchanged.

## [v1.2.0] - 2026-10-17
### Added
- Chronological out-of-time evaluation: strict train (pre-2020) / validate (2021-2022) / test (2023+) splits with contiguous real-history paths, COVID crash stress set, and paired strategy comparison on identical paths.
- Crash-robustness upgrade: 2008 crisis training data, crash-regime features (volatility ratio, drawdown, panic indicator, lagged VIX), crash-weighted breach penalty, and a CPPI-constrained allocator where the network picks assets and a classical risk layer caps total exposure.
- Full ablation study (A-G plus leave-one-out) proving each component's contribution.

### Results
- COVID crash (held out of training): breach rate 24% → 0%, terminal wealth 97.03 → 98.37, beating classic CPPI (96.59).
- 2008 training data alone was the biggest single improvement.

### Tests
- 78 passing (was 52), including causality regression tests for all new features.

## [v1.1.0] - 2026-10-16

### Fixed
- Look-ahead leakage in the decision-time features (`_vol_features` in `src/dhl/experiments/cppi_learned.py`, `_trail_features` in `src/dhl/experiments/cppi_multi.py`). Both builders included the return from price `i` to price `i+1` in the feature vector used to choose the allocation at time `i`. They now use strictly past returns only, and the empty first-step window yields exactly `0.0`. Added regression tests pinning temporal causality (perturbing price `i+1` leaves features at times `<= i` unchanged) and the exact-zero first step.
- Reran all experiments on the corrected features and updated the README tables. Corrected single-asset 63d learned numbers: E[wealth] 102.00 to 101.70, std 4.28 to 3.63, P(breach) 0.004 to 0.003. Multi-asset and cross-decade numbers moved only in the third decimal. The conclusions are unchanged.
